Claude Code — Complete Security Protection & Audit

Purpose: Protect existing database, server, computer, application, and business data.

Security Mode: READ-ONLY AUDIT FIRST

1. Critical Security Rules

Claude Code must follow these rules throughout the project:

Never delete existing files or folders.
Never delete or modify existing database records.
Never execute DROP, TRUNCATE, or DELETE SQL commands.
Never change existing database schemas without approval.
Never modify production server configurations without approval.
Never restart or stop existing server services.
Never expose passwords, API keys, tokens, or connection strings.
Never upload private project data to external services.
Never install or uninstall software without approval.
Never change existing business logic without approval.
Never run destructive penetration tests.
Always preserve existing application functionality.
Always request approval before security remediation. 2. Database Security Audit

Inspect the existing database without modifying it.

Check:

SQL injection vulnerabilities.
Unauthorized database access.
Weak authentication.
Excessive database privileges.
Database connection security.
Sensitive information exposure.
Password hashing security.
Database backup and recovery.
Encryption of sensitive information.
Remote database access restrictions.

Important: Never display actual passwords or sensitive database records.

3. Server Security Audit

Inspect the existing server without changing configurations.

Check:

Operating system security.
Open network ports.
Firewall configuration.
SSL/TLS certificates.
Server authentication.
SSH/RDP access.
Web server security.
API endpoint security.
File and folder permissions.
Server software versions.
Logging and monitoring.
Backup and disaster recovery.

Do not stop services or change firewall rules.

4. Computer Security Audit

Inspect the authorized development environment.

Check:

Exposed credentials.
Insecure environment variables.
Project folder permissions.
Suspicious project scripts.
Vulnerable development dependencies.
Insecure local configurations.
Accidental exposure of private files.
Unsafe command execution.

Do not inspect unrelated personal files.

5. Application Security Audit

Inspect the entire application.

Check:

Authentication and authorization.
SQL injection.
Cross-site scripting (XSS).
Cross-site request forgery (CSRF).
API security.
Session management.
Password storage.
File upload security.
Input validation.
Output encoding.
Dependency vulnerabilities.
Error handling.
Logging and auditing.

Preserve existing application functionality.

6. Backup and Recovery Protection

Verify:

Existing database backup availability.
Backup integrity.
Backup restoration procedures.
Server backup availability.
Configuration backup.
Recovery procedures.
Backup access restrictions.

Do not overwrite or delete existing backups.

7. Security Report Requirements

Generate a detailed report containing:

Priority Description
Critical Immediate security risk
High Serious security weakness
Medium Security improvement required
Low Recommended improvement
Informational General security observation

For each finding, provide:

Vulnerability description.
Affected file or component.
Potential business impact.
Risk level.
Recommended solution.
Required backup.
Possible downtime.
Whether approval is required.

Never include actual secrets in the report.

8. Remediation Approval Process

After completing the audit:

Stop and present the report.
Identify critical vulnerabilities first.
Explain each recommended change.
Identify possible side effects.
Explain backup requirements.
Wait for my explicit approval.
Implement only approved changes.
Verify the result after each change.
Preserve existing functionality.
Report all modifications.

Never automatically repair production systems.

My highest priority is protecting:

Existing business logic.

Existing production services.
